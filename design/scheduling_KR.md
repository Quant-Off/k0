# 태스크와 스케줄링

[English](scheduling.md)

이 문서는 K0가 태스크를 표현하는 방법, 사용자 공간이 태스크를 만들고 시작하는 방법, 라운드 로빈 스케줄러가 태스크 사이를 전환하는 방법을 설명합니다. 코드는 `crates/k0-task/src/lib.rs`, `crates/k0-sched/src/lib.rs`, 그리고 `kernel/src/main.rs`의 `sys_tcb_configure`, `sys_tcb_resume`, `kill_current`에 있습니다.

## 태스크 제어 블록

태스크 제어 블록(TCB)은 다음을 담고 있습니다.

- 태스크의 저장된 사용자 컨텍스트: 범용 레지스터 31개, 스택 포인터, 반환 주소, 저장된 프로세서 상태, EL0 스레드 포인터 레지스터 2개
- 태스크의 최상위 페이지 테이블의 물리 주소
- 태스크의 상태
- 태스크가 속한 큐에서 다음 TCB로 가는 링크
- [ipc_KR.md](ipc_KR.md)에서 설명하는 1회성 응답 자격

루트 태스크의 TCB는 커널 이미지 안의 static입니다. 그 외 모든 TCB는 사용자 공간이 untyped 메모리에서 retype한 그래뉼 크기 프레임의 시작 부분에 있습니다([capabilities_KR.md](capabilities_KR.md) 참고). 커널은 자신의 별칭을 통해서만 이 TCB에 접근하며, EL0에는 매핑되지 않습니다. 컴파일 타임 assertion이 TCB를 그래뉼보다 작게 유지합니다.

## 상태

| 상태 | 의미 |
| --- | --- |
| `Inactive` | retype 직후, 구성 전 |
| `Stopped` | 구성 완료, 아직 시작 전 |
| `Ready` | 준비 큐에 있음 |
| `Running` | 현재 실행 중인 태스크 |
| `BlockedSend`, `BlockedRecv`, `BlockedCall` | 엔드포인트 큐에서 대기 중 |
| `BlockedReply` | `CALL`의 응답을 기다리는 중 |
| `Dead` | 스스로 종료했거나 강제 종료됨 |

`Inactive`의 값은 0입니다. 새로 retype한 프레임은 전부 0이므로, 이미 큐 링크가 비어 있고 응답 자격이 없는 유효한 `Inactive` TCB입니다. retype에는 생성자가 필요 없습니다.

## 태스크 생성

**`TCB_CONFIGURE`** 는 `Tcb` 케이퍼빌리티, 진입 주소, 스택 상단, `AddrSpace` 케이퍼빌리티를 받습니다. 커널은 다음을 검사합니다.

- 진입 주소가 4바이트 정렬이고, 첫 번째 그래뉼보다 위에 있으며, 48비트 사용자 범위 안에 있음
- 스택 상단이 16바이트 정렬이고, 첫 번째 그래뉼보다 위에 있으며, 사용자 범위 안에 있음
- TCB가 `Inactive` 상태임. 따라서 각 TCB는 한 번만 설정할 수 있고, 실행 중인 태스크를 다시 설정할 수는 없음
- 케이퍼빌리티가 retype된 `Tcb`임. 루트 태스크 자신의 `RootTcb`는 거부됨

그런 다음 커널은 저장된 컨텍스트를 0으로 채우고 진입 주소와 스택 포인터를 설정합니다. 저장된 프로세서 상태는 커널이 직접 설정하며, 인터럽트가 마스크되지 않은 EL0로 지정합니다. 사용자 공간은 프로세서 상태를 제공하지 않으므로, EL1로 복귀하거나 인터럽트를 마스크한 채 실행하도록 요청할 수 없습니다. 스레드 포인터 레지스터는 0으로 시작하므로, 새 태스크가 생성자의 값을 물려받지 않습니다. TCB는 `Stopped`로 이동합니다.

**`TCB_RESUME`** 은 `Stopped` TCB만 받아들이고 준비 큐에 넣습니다. 이미 큐에 있거나, 실행 중이거나, 블록되었거나, 죽은 TCB는 거부하므로 같은 TCB가 큐에 두 번 들어갈 수 없습니다.

## 준비 큐

스케줄러는 값 세 개를 유지합니다. 현재 태스크, 그리고 준비 큐의 head와 tail입니다. 각각 TCB의 커널 주소이며 0은 없음을 뜻합니다. 큐는 TCB 자신의 `next` 필드로 연결되므로 별도의 메모리가 필요 없습니다. 큐의 길이는 TCB 개수로 제한되며, 이 TCB들의 비용은 사용자 공간이 untyped 메모리로 지불했습니다. 따라서 스케줄러가 커널 메모리를 고갈시키는 수단이 될 수 없습니다.

같은 `next` 필드는 블록된 태스크를 엔드포인트 큐에 연결할 때도 쓰입니다. 상태 기계가 이 용도들을 구분합니다. 태스크는 준비 상태이거나, 하나의 엔드포인트에서 블록되었거나, 실행 중이며, 둘 이상에 동시에 속하지 않습니다.

## 태스크 전환

예외가 EL0에서 도착하면, 벡터 코드는 Rust 코드가 실행되기 전에 모든 사용자 레지스터를 현재 TCB의 컨텍스트에 저장합니다([exceptions_KR.md](exceptions_KR.md) 참고). 복귀할 때는 전역 `__current_context` 포인터가 가리키는 컨텍스트에서 레지스터를 복원합니다. 따라서 태스크 전환은 두 단계뿐입니다.

1. `__current_context`가 다음 태스크의 저장된 컨텍스트를 가리키게 합니다.
2. 다음 태스크가 다른 최상위 페이지 테이블을 쓴다면 이를 `TTBR0_EL1`에 로드하고 TLB 전체를 무효화합니다. K0는 아직 주소 공간 식별자를 사용하지 않습니다.

이 전환을 사용하는 연산은 네 가지입니다.

| 동작 | 사용처 | 현재 태스크에 일어나는 일 |
| --- | --- | --- |
| `rotate` | `YIELD`, 타이머 선점 | 준비 큐의 꼬리로 갑니다. 다른 준비된 태스크가 없으면 그대로 계속 실행됩니다. |
| `block_and_switch` | IPC | 준비 큐 밖에 머뭅니다. 호출자가 이미 엔드포인트 큐나 응답 자격에 걸어 두었습니다. |
| `exit_current` | `EXIT`, 폴트 | `Dead`가 됩니다 |
| `handoff` | 부팅 때 한 번 | 루트 태스크가 첫 `Running` 태스크가 됩니다 |

## 선점

타이머는 초당 한 번 발생합니다. EL0가 실행 중일 때 타이머가 발생하면 IRQ 경로가 이를 확인하고, 타이머를 다시 설정하고, `k0: tick N`을 출력하고, `k0_preempt`를 호출하며, 이 함수가 `rotate`를 호출합니다. 따라서 양보하지 않는 태스크도 최대 1초 뒤에는 CPU를 잃습니다.

커널 자체는 선점되지 않습니다. 예외 진입이 인터럽트를 마스크하고, 커널은 시스템 콜이나 폴트를 처리하는 동안 마스크를 유지합니다. EL1에서 타이머 인터럽트가 도착하는 것은 이양 이전의 부팅 중에만 가능하며, 이때는 틱을 세기만 합니다.

## 실행할 것이 남지 않았을 때

- 현재 태스크가 종료되거나 죽었는데 준비된 태스크가 없으면 `exit_current`가 이를 보고하고, 커널은 `k0: all tasks exited`를 출력한 뒤 파킹합니다.
- 현재 태스크가 IPC에서 블록되었는데 준비된 태스크가 없으면 `block_and_switch`가 이를 보고하고, 커널은 `k0: all tasks blocked`를 출력한 뒤 파킹합니다. Notification 오브젝트가 아직 없으므로 현재는 다른 어떤 이벤트도 태스크를 깨울 수 없습니다. 이것이 [SECURITY_KR.md](../SECURITY_KR.md)의 어드바이저리 GHSA-q99x-2wrv-358p입니다.

태스크가 죽기 전에 `kill_current`는 그 태스크가 가진 응답 자격을 회수합니다. 그 응답을 기다리던 태스크는 `NO_REPLY`와 함께 깨어나며, 영원히 블록된 채로 남지 않습니다.

## 테스트 방법

이 경로들은 시스템 레지스터를 읽으므로 호스트가 아니라 부팅으로 테스트합니다. 루트 태스크 자가 테스트는 다음을 수행합니다.

- 타겟까지 세고 종료하는 태스크를 만들고 기다림
- 설정되지 않은 태스크의 재개를 거부하고, 태스크의 두 번째 재개를 거부하고, 죽은 태스크의 재개를 거부함
- 양보 없이 영원히 도는 태스크를 시작한 뒤, 타이머 선점을 통해 루트 태스크가 CPU를 다시 얻는지 확인함
- 스레드 포인터 레지스터가 태스크 사이에서 누출되지 않는지 확인함

`tools/qemu-boot-test.sh`는 `root: child exit test pass`, `root: preempt test pass`, `root: sched tests pass`를 요구하고, 이어서 타이머 틱이 적어도 한 번 더 나오기를 요구합니다.

## 알려진 공백

- 스케줄링은 고정 1초 슬라이스의 단순 라운드 로빈입니다. 우선순위와 예산이 없습니다.
- 유휴 상태가 없습니다. 루트 태스크는 자가 테스트를 마친 뒤 `YIELD`를 계속 호출하는 루프로 끝나므로, CPU는 절대 잠들지 않습니다.
- 타임아웃이 없습니다. 블록된 태스크는 IPC 상대방이 동작할 때만 깨어납니다.
- 코어는 하나뿐입니다.
- 죽은 TCB는 회수되지 않으며, 그 메모리는 untyped 케이퍼빌리티로 반환되지 않습니다.
- 모든 태스크가 루트 태스크의 주소 공간에서 실행되므로, 실제로는 전환 시 `TTBR0_EL1`이 바뀌지 않습니다.
