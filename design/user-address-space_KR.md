# 사용자 주소 공간

[English](user-address-space.md)

이 노트는 K0가 부팅할 때 루트 태스크의 주소 공간을 어떻게 만들고, 이후 사용자 공간이 `MAP` 시스템 콜로 그것을 어떻게 확장하는지 설명합니다. 코드는 `crates/k0-mm/src/user.rs`, `crates/k0-task/src/lib.rs`(`spawn_root`), `kernel/src/main.rs`의 `sys_map`에 있습니다.

## 부트 프레임 윈도우

루트 태스크가 생기기 전에 커널은 루트 태스크의 이미지, 스택, 페이지 테이블, bootinfo 페이지를 담을 메모리가 필요합니다. `kernel_main`은 이를 위해 커널 이미지 바로 뒤의 RAM 2 MiB를 윈도우로 예약합니다([boot_KR.md](boot_KR.md) 참고). `FrameAlloc`은 이 윈도우에서 프레임을 차례로 내주며 해제는 하지 않습니다. 각 프레임은 내주기 전에 커널 별칭을 통해 0으로 채웁니다.

루트 CNode를 채울 때 이 윈도우는 예약된 영역으로 기록되므로 어느 부분도 untyped 메모리가 되지 않습니다. 루트 태스크가 자신의 페이지 테이블이 든 프레임을 retype하는 일은 없습니다.

## 루트 태스크의 테이블 만들기

`spawn_root`는 무결성 검사를 이미 통과한 루트 태스크 이미지([hardening_KR.md](hardening_KR.md) 참고)를 받아 다음을 수행합니다.

1. 평평한 이미지를 연속된 프레임에 복사하고 명령 캐시를 동기화합니다. 복사는 데이터 쓰기였고 EL0가 곧 이를 실행하기 때문입니다.
2. `UserSpace::new`로 빈 레벨 0 테이블을 만듭니다.
3. 빌드 시점 메타데이터에 따라 모든 세그먼트를 매핑합니다. 각 세그먼트는 이미지 안에서 그래뉼 경계에 시작해야 하고, 이미지 안에서 끝나야 하며, 크기가 0이 아니어야 합니다. 진입점은 이미지 안에 있어야 하고, text가 아닌 세그먼트에 있어서는 안 됩니다.
4. `0x1000_0000` 바로 아래에 64 KiB 스택을 매핑합니다. 스택 아래의 그래뉼은 가드로 매핑하지 않은 채 둡니다.
5. bootinfo 페이지를 `0x0F00_0000`에 읽기 전용으로 매핑합니다.
6. 루트 TCB의 저장된 컨텍스트를 채웁니다. 프로그램 카운터는 진입점, 스택 포인터는 스택 꼭대기, 저장된 프로세서 상태는 인터럽트를 마스크하지 않은 EL0입니다.

`UserSpace::map_range`는 그래뉼에 정렬되지 않은 범위, 첫 번째 그래뉼을 매핑하게 되는 범위, 48비트 사용자 절반을 넘어서는 범위를 모두 거부합니다. 첫 번째 그래뉼은 절대 매핑되지 않으므로 사용자 공간의 null 포인터 역참조는 항상 폴트를 냅니다.

## 사용자 권한

| 종류 | 용도 | EL0 | EL1 |
| --- | --- | --- | --- |
| `TextUser` | 루트 태스크 코드 | 읽기와 실행 | 읽기, 실행 불가 |
| `RoUser` | 읽기 전용 데이터, bootinfo, 읽기 전용 프레임 | 읽기 | 읽기, 실행 불가 |
| `RwUser` | 데이터, 스택, 읽기·쓰기 프레임 | 읽기와 쓰기 | 읽기와 쓰기, 실행 불가 |

모든 사용자 매핑은 `PXN`을 설정하므로 커널이 사용자 메모리를 실행하는 일은 없습니다. `UXN`을 해제하는 것은 `TextUser`뿐이고, `TextUser`는 읽기 전용입니다. `TextUser` 매핑은 부트 빌더만 만들 수 있습니다. `MAP` 시스템 콜은 읽기 전용과 읽기·쓰기만 받으므로, 부팅 이후에는 새 실행 가능 사용자 메모리가 생길 수 없습니다.

## `TTBR0` 전환

`install_user_ttbr0`는 identity 매핑을 루트 태스크의 테이블로 바꾸고 TLB를 무효화합니다. 이 시점부터 물리 주소를 포인터로 쓰는 것은 커널에게 의미가 없습니다. 콘솔, GIC, DTB, 모든 페이지 테이블은 이미 커널 별칭을 통해 접근하고 있으며, 그래서 이 전환이 `kernel_main`의 늦은 시점에 일어납니다.

전환 직후 `check_user_wx`가 주소 변환 명령으로 결과를 검사합니다.

| 검사 | 기대 결과 |
| --- | --- |
| EL0에서 사용자 text를 읽을 수 있음 | 예 |
| EL0에서 사용자 text에 쓸 수 있음 | 아니오 |
| EL0에서 사용자 스택의 맨 위 페이지에 쓸 수 있음 | 예 |
| EL0에서 사용자 스택 가드 페이지를 읽을 수 있음 | 아니오 |
| EL0에서 커널 text를 읽을 수 있음 | 아니오 |
| EL0에서 bootinfo를 읽을 수 있음 | 예 |
| EL0에서 bootinfo에 쓸 수 있음 | 아니오 |
| EL1에서 사용자 text를 읽을 수 있음 | PAN을 검사할 수 있으면 아니오, 아니면 예 |
| 커널 text의 예전 identity 매핑을 읽을 수 있음 | 아니오 |

PAN 검사에는 FEAT_PAN2의 `AT S1E1RP` 명령이 필요합니다. 이 명령이 없는 CPU에서는 페이지 권한으로 대체하며, 이 권한은 EL1이 사용자 text를 읽는 것을 허용합니다.

## 실행 중 주소 공간 확장

이양 이후 루트 태스크는 `MAP`으로 매핑을 추가합니다. 커널은 설치된 테이블을 별칭을 통해 워크하며, 한 가지 확고한 규칙이 있습니다. **실행 중의 워커는 페이지 테이블을 절대 할당하지 않습니다.**

- `user_map_frame`으로 **`Frame` 케이퍼빌리티를 매핑**하면 리프 엔트리 하나를 만듭니다. 도중에 중간 테이블이 없으면 호출은 `MISSING_TABLE`로 실패합니다. 리프는 비어 있어야 하며, 그렇지 않으면 호출은 `OVERLAP`으로 실패합니다.
- `user_install_table`로 **`PageTable` 케이퍼빌리티를 매핑**하면 주어진 주소의 경로를 따라 내려가며 처음 만나는 빈 레벨에 테이블을 연결합니다. 경로가 리프 레벨까지 이미 완성되어 있으면 호출은 `OVERLAP`으로 실패합니다.

따라서 사용자 공간은 `PageTable` 오브젝트를 retype하는 방식으로, 자신의 untyped 메모리를 들여 자기 페이지 테이블 비용을 직접 부담합니다. 커널의 정적 테이블 풀은 사용자 매핑에 대해 소모되지 않습니다.

`sys_map`의 추가 규칙은 다음과 같습니다.

- 타겟 주소 공간은 항상 `x3`의 `AddrSpace` 케이퍼빌리티로 지정합니다. 커널은 "현재 주소 공간"을 가정하지 않습니다.
- 각 `Frame`과 각 `PageTable` 케이퍼빌리티는 한 번만 매핑할 수 있습니다. 케이퍼빌리티의 플래그가 이를 기록하며, 두 번째 시도는 `ALREADY_MAPPED`로 실패합니다.
- `Tcb`와 `Endpoint` 케이퍼빌리티는 아예 매핑할 수 없습니다. 커널 오브젝트는 EL0에서 절대 보이지 않습니다.
- 워크 중에 발견한 손상된 엔트리는 커널 불변식 위반으로 취급합니다. 커널은 `k0: user page table corrupt`를 출력하고 파킹합니다.

## PAN과 사용자 메모리에 대한 커널 접근

CPU에 FEAT_PAN이 있으면 커널은 PAN을 설정한 채 실행되므로, 사용자 가상 주소를 통한 EL1 접근은 모두 폴트가 납니다. K0는 지금 이것이 문제가 되지 않도록 만들어져 있습니다. 커널은 사용자 프레임을 자신의 별칭을 통해서만 건드리고, 어떤 시스템 콜도 사용자 버퍼를 읽거나 쓰지 않습니다. 사용자 메모리를 복사해야 하는 시스템 콜이 앞으로 생긴다면 권한 없는 로드·스토어 명령(`LDTR`, `STTR`)을 써야 합니다.

## 테스트 방법

- `crates/k0-mm/src/user/tests.rs`의 호스트 단위 테스트는 모든 사용자 권한의 W^X 속성과, 어떤 테이블도 건드리기 전에 잘못된 입력을 거부해야 하는 검증 경로를 확인합니다.
- 루트 태스크 자가 테스트는 실행 중 경로를 점검합니다. 페이지 테이블이 생기기 전의 매핑, 잘못된 주소 공간으로의 매핑, 이중 매핑, null 주소 매핑, 잘못된 권한, 겹치는 매핑, 그리고 새 매핑을 통한 읽기와 쓰기입니다.
- `tools/qemu-boot-test.sh`는 `k0: user w^x checks pass`와 `root: retype/map tests pass`를 요구합니다.

## 알려진 공백

- 주소 공간은 루트 태스크의 것 하나뿐입니다. `AddrSpace`를 아직 retype할 수 없으므로 모든 태스크가 그 안에서 실행됩니다. 이것은 [SECURITY_KR.md](../SECURITY_KR.md)의 어드바이저리 GHSA-vmpv-qc49-3p6r에 포함됩니다.
- 매핑을 제거할 수 없습니다.
- 사용자 공간에 매핑된 모든 프레임은 커널 별칭에도 읽기·쓰기로 매핑되어 있습니다. retype 중에 커널이 그곳에서 프레임을 0으로 채웠기 때문입니다.
