# 부팅과 higher-half로의 점프

[English](boot.md)

이 노트는 첫 명령에서 루트 태스크가 EL0에서 실행되는 순간까지 K0를 따라갑니다. `kernel/src/arch/aarch64/boot.S`, `kernel/src/main.rs`의 `kernel_init`과 `kernel_main`, 링커 스크립트 `kernel/virt.ld`와 `kernel/apple.ld`를 다룹니다.

## 진입 규약

K0는 Linux arm64 Image로 적재됩니다. 이미지의 처음 64바이트는 Image 헤더이며, 실제 진입점으로의 분기, 적재 오프셋, 이미지 크기, 플래그, `ARM\x64` 매직으로 이루어집니다. 오프셋, 크기, 플래그는 링커 스크립트가 채웁니다. QEMU와 m1n1은 모두 이 헤더를 인식하고 Linux 부트 프로토콜로 커널에 진입합니다.

- `x0`에 디바이스 트리 블롭(DTB)의 물리 주소가 들어 있습니다.
- MMU와 데이터 캐시는 꺼져 있습니다.
- CPU는 EL2 또는 EL1에 있습니다.

커널은 higher-half 가상 주소(`0xFFFF_0000_0000_0000`에 물리 적재 주소를 더한 값)로 링크되지만, 실행은 물리 적재 주소에서 시작합니다. 이 노트의 모든 내용은 이 간격에서 비롯됩니다.

## 페이즈 0: `boot.S`

어셈블리 진입부는 Rust에 안전하게 도달하는 데 필요한 최소한의 일만 하고, 예상 밖의 상황이면 코어를 `wfe` 루프에 파킹합니다.

1. **모든 예외를 마스크합니다.** 아직 벡터 테이블이 설치되지 않았으므로, 예외가 발생하면 동작이 정의되지 않습니다.
2. **부트 코어를 고릅니다.** `MPIDR_EL1`의 전체 affinity 값(Aff3, Aff2, Aff1, Aff0)을 0과 비교합니다. Apple Silicon은 클러스터 번호를 Aff1에 넣기 때문에, Aff0만 확인하면 모든 클러스터의 코어 0이 통과합니다. 다른 코어는 모두 파킹합니다. K0는 현재 싱글 코어입니다.
3. **예외 레벨을 확인합니다.** EL1이면 계속 진행합니다. EL2이면 EL1으로 내려갑니다. EL0과 EL3이면 파킹합니다.
4. **EL2에서 EL1으로 내려갑니다.** `HCR_EL2.RW`로 EL1을 AArch64로 만듭니다. `HCR_EL2.HCD`는 EL1에서 `hvc`를 정의되지 않은 명령으로 만듭니다. EL2에는 벡터 테이블이 없어 EL2로의 트랩이 원인 진단 없이 멈추기 때문입니다. CPU에 포인터 인증이 있으면 `HCR_EL2.APK`와 `HCR_EL2.API`가 EL1의 키 접근과 PAC 명령 사용이 EL2로 트랩되는 것을 막습니다. 코드는 EL1에 물리 타이머와 카운터를 주고, 가상 카운터 오프셋을 0으로 만들며, FP/SIMD, 시스템 레지스터, 디버그, PMU에 대한 EL2 트랩을 해제합니다. 그런 다음 모든 예외를 마스크한 채 EL1h로 복귀합니다.
5. **EL1을 정규화합니다.** 부트로더가 무엇을 남겼든 `SCTLR_EL1`을 알려진 값으로 설정합니다. MMU와 캐시는 꺼지고, 리틀 엔디언이며, EL0와 EL1에서 스택 정렬 검사를 하고, EL0의 `WFI`와 `WFE`는 트랩되며, EL0의 인터럽트 마스크 비트 접근은 거부됩니다. `CPACR_EL1`은 0으로 설정되어 FP/SIMD, SVE, SME 명령이 EL0와 EL1 모두에서 트랩됩니다. 커널은 소프트 float 타겟으로 빌드되며 태스크용 벡터 레지스터 상태를 보관하지 않습니다.
6. **부트 스택을** `__boot_stack_top`으로 설정하고, **`.bss`를 0으로 채운 뒤** `kernel_init(x0)`을 호출합니다. 그 과정에서 `x0`을 건드리지 않으므로 DTB 주소가 첫 번째 인자로 전달됩니다.

## `kernel_init`: 점프 이전

`kernel_init`은 MMU가 꺼진 채 물리 적재 주소에서 실행됩니다. 프로그램 카운터 기준으로 주소를 만드는 코드(`adr`, `adrp`)는 올바른 물리 주소를 얻습니다. 그러나 절대 포인터를 담은 데이터는 링커가 higher-half 주소로 재배치해 두었습니다. static에 저장된 문자열 슬라이스, vtable, `core::fmt` 기계장치가 여기에 해당합니다. 이런 포인터를 역참조하면 지금은 폴트가 납니다. 그래서 이 단계는 리터럴 문자열과 16진 정수만 출력하고, `writeln!`이 필요한 일은 하지 않습니다.

이 단계는 네 가지 일을 합니다.

1. **예외 벡터를 설치합니다.** 물리 주소로 설치하므로, 이후에 폴트가 나면 멈추지 않고 진단을 출력합니다.
2. **`k0_boot::dtb_span`으로 DTB 헤더만 읽습니다.** 매직과 전체 크기를 읽으며, 주소는 8바이트 정렬이고 null이 아니어야 하고 크기는 40바이트 이상 2 MiB 이하여야 합니다. 전체 파싱에는 재배치된 데이터가 필요하므로 점프 이후로 미룹니다. 점프 전에 DTB를 매핑해야 하므로 크기는 지금 필요합니다.
3. **`k0_mm::enable_paging`으로 MMU를 켭니다.** 레이아웃은 링커 심볼에서 가져옵니다. text, 읽기 전용 데이터, 데이터와 `.bss`, 부트 스택, DTB, UART용 디바이스 윈도우, 그리고 QEMU에서는 GICv3 distributor와 redistributor 윈도우가 대상입니다. 모든 것을 두 번 매핑합니다. 한 번은 물리 주소(identity, `TTBR0`를 통해), 한 번은 higher-half 별칭(`TTBR1`을 통해)입니다. 테이블과 권한은 [memory_KR.md](memory_KR.md)에서 설명합니다.
4. **점프합니다.** 인라인 어셈블리가 스택 포인터에 별칭 오프셋을 더하고, `movz`와 `movk`로 `kernel_main`의 절대 주소를 만든 뒤, `x0`에 DTB 주소를 그대로 둔 채 그곳으로 분기합니다.

## `kernel_main`: 점프 이후

프로그램 카운터와 스택 포인터는 이제 higher-half에 있고, 재배치된 데이터가 유효하며, 일반적인 Rust가 동작합니다. 아래 단계의 순서가 곧 보안 논거이므로 `kernel_main`은 하나의 직선 시퀀스입니다. 점프 이전에는 `Mmu`와 `Vectors` 같은 typestate 토큰이 한 단계가 다른 단계보다 먼저 일어났음을 증명합니다. 이 토큰은 점프를 넘을 수 없으므로, 점프 이후에는 코드의 순서가 그 보장을 대신합니다. 실패하면 모두 이유를 출력하고 코어를 파킹합니다.

| 로그 줄 | 단계 |
| --- | --- |
| `k0: higher half (pc = ...)` | 벡터를 가상 주소로 다시 설치합니다. 초기 콘솔이 별칭으로 전환되므로 identity 매핑이 사라진 뒤에도 계속 동작합니다. |
| `k0: w^x checks pass (granule 4K, wxn)` | 주소 변환 명령으로 text는 읽을 수 있고 쓸 수 없으며, 읽기 전용 데이터는 쓸 수 없고, 스택 가드 페이지는 매핑되지 않았으며, 스택은 쓸 수 있음을 확인합니다. |
| `k0: memory ...` | 별칭을 통해 DTB를 파싱합니다. 파서는 [dtb_KR.md](dtb_KR.md)에서 다룹니다. 메모리 맵은 어떤 커널 MMIO 윈도우와도 겹치면 안 됩니다. |
| `k0: root task integrity ok (...)` | 내장 루트 태스크 이미지를 다시 해시하고 빌드 시점에 고정된 해시와 비교합니다. |
| `k0: entropy ...`, `k0: pac=... bti=... pan=...` | PAC 키를 파생해 적재하고, PAN을 켜고, 카운터·디버그·PMU에 대한 EL0 접근을 끕니다. [hardening_KR.md](hardening_KR.md)를 참고하세요. |
| `k0: irq on (timer 1s)` | GIC(QEMU에서)와 타이머를 설정하고 IRQ와 SError의 마스크를 해제합니다. |
| `k0: kernel table pool N/32` | 2 MiB 부트 프레임 윈도우를 고르고 매핑합니다. |
| `k0: root task loaded (...)` | 루트 태스크를 윈도우의 프레임에 복사하고 주소 공간을 만듭니다. [user-address-space_KR.md](user-address-space_KR.md)를 참고하세요. |
| `k0: untyped ...`, `k0: root cnode ready (...)` | 루트 CNode를 채웁니다. 비어 있는 물리 범위는 모두 untyped 케이퍼빌리티가 됩니다. [capabilities_KR.md](capabilities_KR.md)를 참고하세요. |
| `k0: bootinfo page ready` | 케이퍼빌리티 목록을 읽기 전용 bootinfo 페이지에 씁니다. |
| `k0: user w^x checks pass` | `TTBR0`가 사용자 테이블을 가리키고, identity 매핑은 사라졌으며, 사용자 매핑을 EL0와 EL1 양쪽에서 검사합니다. |
| `k0: entering root task (el0)` | `k0_sched::handoff`가 EL0로 진입합니다. |

### 부트 프레임 윈도우 고르기

`pick_window`는 커널 이미지 바로 뒤에서 2 MiB의 RAM을 찾습니다. 후보가 DTB나 펌웨어 예약 영역과 겹치면 장애물을 지나친 위치로 옮겨 다시 시도하며, 최대 64라운드까지 반복합니다. 윈도우 전체가 DTB의 메모리 영역 하나 안에 들어갈 때만 범위를 반환합니다. 윈도우에는 루트 태스크 이미지, 스택, 페이지 테이블, bootinfo 페이지가 들어갑니다. 윈도우는 untyped 케이퍼빌리티에서 제외되므로, 커널이 아직 쓰는 메모리를 루트 태스크가 retype하는 일은 없습니다.

### 이양 이후

`handoff`는 루트 태스크를 실행 중인 태스크로 기록하고, 벡터 코드가 루트 태스크의 저장된 컨텍스트를 가리키게 하고, 커널 스택을 꼭대기로 되감은 뒤, 이후의 모든 복귀가 쓰는 것과 같은 경로로 EL0에 복귀합니다. 이때부터 커널 코드는 예외에 대한 응답으로만 실행됩니다. 시스템 콜, 폴트, 타이머 인터럽트가 그 예외입니다. 이 경로는 [exceptions_KR.md](exceptions_KR.md)에서 설명합니다.

## 테스트 방법

`tools/qemu-boot-test.sh`는 디버그 커널을 QEMU에서 부팅하고 위의 로그 줄을 순서대로 확인한 뒤 루트 태스크 자가 테스트를 확인합니다. 어느 단계든 실패 줄이 나오면 테스트가 실패합니다. `kernel_main` 안의 자가 검사도 그 자체로 테스트입니다. 매핑이 잘못되면 실패한 검사의 이름과 함께 부팅이 멈춥니다.

## 알려진 공백

- 코어 하나만 실행됩니다. 다른 코어는 `boot.S`에서 영원히 파킹합니다.
- Apple Silicon 빌드는 CI에서 컴파일되지만 아직 실기에서 부팅해 보지 않았습니다.
- 커널은 항상 같은 가상 주소에 놓입니다. 주소 무작위화가 없습니다.
- 릴리스 빌드는 패닉 때 아무것도 출력하지 않습니다. 의도한 동작이지만, 릴리스 빌드에서는 패닉이 나도 진단을 얻을 수 없다는 뜻이기도 합니다.
