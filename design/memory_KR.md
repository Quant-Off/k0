# 커널 페이지 테이블과 W^X

[English](memory.md)

이 노트는 커널이 자기 자신을 매핑하는 방법을 설명합니다. 변환 설정, 정적 테이블 풀, 권한 체계, 그리고 부팅 때 결과를 확인하는 검사를 다룹니다. 코드는 `crates/k0-mm/src/paging.rs`에 있습니다. 사용자 주소 공간은 [user-address-space_KR.md](user-address-space_KR.md)에서 다룹니다.

## 두 개의 절반

AArch64는 가상 주소 공간을 두 개의 테이블 루트로 나눕니다.

- **`TTBR0_EL1`**은 아래쪽 절반을 담당합니다. 부팅 중에는 각 가상 주소가 물리 주소와 같은 identity 매핑을 담고 있습니다. MMU가 켜지는 순간 커널이 계속 실행되려면 이 매핑이 필요합니다. 이후 `TTBR0_EL1`은 루트 태스크의 테이블로 전환되고 identity 매핑은 사라집니다.
- **`TTBR1_EL1`**은 위쪽 절반을 담당합니다. 고정된 오프셋으로 만든 물리 메모리의 커널 별칭을 담고 있습니다. 가상 주소 = 물리 주소 + `0xFFFF_0000_0000_0000`입니다. higher-half로 점프한 뒤 커널은 이 별칭만 사용합니다.

두 절반 모두 48비트 가상 주소(`T0SZ = T1SZ = 16`)와 4단계 테이블을 사용합니다. 그래뉼은 QEMU virt에서 4 KiB, Apple Silicon에서 16 KiB이며 `plat-virt` 또는 `plat-apple` feature로 선택합니다. `TG0`와 `TG1`은 같은 그래뉼을 서로 다른 값으로 인코딩하는데, 코드는 이를 명시적으로 처리합니다. 물리 주소 크기(`IPS`)는 CPU가 보고하는 범위에서 가져오되 48비트로 제한합니다.

커널은 페이지만 매핑하고 블록은 매핑하지 않습니다. 모든 매핑이 마지막 레벨까지 같은 워크를 거치므로, 따져봐야 할 코드 경로가 하나뿐입니다.

## 정적 테이블 풀

커널에는 heap이 없습니다. 페이지 테이블은 `.bss`에 있는 32개 테이블 풀에서 나오며, 증가만 하는 카운터로 하나씩 내줍니다. 테이블 두 개는 두 절반의 루트가 됩니다. 그 밖의 테이블은 매핑이 추가되면서 중간 테이블이 됩니다. QEMU virt에서는 부팅이 끝났을 때 32개 중 17개를 사용합니다.

워크가 기존 테이블 엔트리를 따라갈 때, `index_of`는 그 엔트리에 든 주소를 풀 인덱스로 되돌립니다. 풀 안에서 할당된 테이블에 정확히 맞지 않는 주소는 거부합니다. 따라서 손상되었거나 위조된 테이블 주소는 `BadTable`로 워크를 멈추게 하며, 임의의 메모리로 따라 들어가는 일은 없습니다.

### 실패한 매핑은 롤백됩니다

`map_page`는 내려가는 길에 만든 모든 링크를 기억합니다. 풀이 바닥나거나 리프 엔트리가 이미 사용 중인 경우 등으로 워크가 실패하면, 그 링크를 지우고 카운터를 되돌립니다. 풀은 호출 전과 정확히 같은 상태로 돌아갑니다.

부팅 이후에 이것이 중요합니다. `RETYPE` 시스템 콜마다 이 풀을 통해 새 오브젝트를 커널 별칭에 매핑합니다. 롤백이 없다면 사용자 태스크가 도중에 실패하는 retype을 반복해서 풀을 테이블 몇 개씩 고갈시킬 수 있고, 결국 커널 자신이 아무것도 매핑하지 못하게 됩니다. 롤백이 있으면 실패한 retype은 비용이 들지 않습니다. 호스트 테스트 두 개가 이를 보여 줍니다. 하나는 워크를 중간에 실패시키고 풀이 그대로인지 확인하며, 다른 하나는 거의 가득 찬 풀에서 천 번 연속으로 실패시킵니다.

## 권한

모든 커널 매핑은 하나의 규칙을 따릅니다. 쓰기 가능하면서 실행 가능한 것은 없고, 커널이 자기 용도로 매핑한 것은 EL0에서 접근할 수 없습니다.

| 종류 | 용도 | EL1 접근 | EL1 실행 | EL0 접근 |
| --- | --- | --- | --- | --- |
| `Text` | 커널 코드 | 읽기 | 가능 | 없음 |
| `Ro` | 읽기 전용 데이터, DTB | 읽기 | 불가 | 없음 |
| `Rw` | 데이터, `.bss`, 스택, 프레임 윈도우 | 읽기와 쓰기 | 불가 | 없음 |
| `Device` | UART, GIC | 읽기와 쓰기 | 불가 | 없음 |

모든 커널 매핑은 `UXN`을 설정하고, `Text`를 제외한 모든 매핑은 `PXN`을 설정합니다. 메모리 속성 인덱스 0은 일반 write-back 메모리이고 인덱스 1은 Device-nGnRE입니다.

`SCTLR_EL1.WXN`은 MMU가 켜질 때 설정됩니다. `WXN`이 있으면 하드웨어는 실행 비트가 무엇이든 쓰기 가능한 페이지에서의 실행을 거부합니다. 버그 때문에 쓰기 가능하면서 실행 가능한 엔트리가 만들어지더라도, 실행 가능한 쓰기 가능 페이지는 생기지 않습니다.

링커 스크립트가 이 구분을 뒷받침합니다. text, 읽기 전용 데이터, 데이터를 그래뉼 경계에 정렬하고, ELF 프로그램 헤더에도 같은 R+X, R, R+W 플래그를 담습니다.

## 가드 페이지

부트 스택은 64 KiB이며 `.bss` 뒤에 있습니다. 그 바로 아래 그래뉼은 두 절반 모두에서 제외되어, 스택 오버플로가 `.bss`를 덮어쓰지 않고 즉시 폴트를 냅니다. 예외 벡터는 `.bss`에 자기만의 8 KiB 스택을 가집니다. 치명적 경로는 이 스택으로 전환하므로, 폴트 자체가 스택 오버플로였더라도 커널은 진단을 출력할 수 있습니다.

## MMU 켜기

`switch_on`은 `MAIR_EL1`, `TCR_EL1`, 두 테이블 루트를 쓴 다음, 배리어를 실행하고 TLB를 무효화하고 명령 캐시 전체를 무효화한 뒤에 `SCTLR_EL1.M`, `C`, `I`, `WXN`을 설정합니다. 부트로더가 캐시에 무엇을 남겼는지 커널은 신뢰하지 않으므로 명령 캐시 무효화를 수행합니다.

`enable_paging`은 한 번만 실행할 수 있습니다. 두 번째 호출은 `AlreadyEnabled`를 반환합니다. 성공하면 페이징이 켜졌음을 증명하는 용도의 `Mmu` 토큰을 반환합니다. 이 토큰은 higher-half로의 점프를 넘어 가져갈 수 없기 때문에 아직 이후 어떤 단계도 이를 소비하지 않으며, 대신 `kernel_main`의 순서가 그 시퀀스를 보장합니다.

## 이후의 매핑 추가

`map_kernel_window`는 부팅 이후 higher-half에 읽기·쓰기 범위를 추가합니다. 두 곳에서 사용합니다.

- 루트 태스크를 적재하기 전, 2 MiB 부트 프레임 윈도우에
- `RETYPE`으로 만든 모든 오브젝트에. 커널이 별칭을 통해 이를 0으로 채우고 사용할 수 있게 하기 위해서입니다.

이 호출들은 유효하지 않은 엔트리를 유효하게 바꾸기만 합니다. 기존 변환은 바뀌지 않으므로 break-before-make 시퀀스가 필요 없습니다. 스토어 배리어와 명령 배리어가 메모리를 사용하기 전에 새 엔트리를 테이블 워커에게 보이게 합니다.

## 부팅 시 자가 검사

점프 직후 `kernel/src/main.rs`의 `check_wx`가 주소 변환 명령(`AT S1E1R`, `AT S1E1W`)으로 각 경우가 의도대로 동작하는지 하드웨어에 묻습니다.

| 검사 | 기대 결과 |
| --- | --- |
| 커널 text를 읽을 수 있음 | 예 |
| 커널 text에 쓸 수 있음 | 아니오 |
| 읽기 전용 데이터에 쓸 수 있음 | 아니오 |
| 부트 스택 가드 페이지를 읽을 수 있음 | 아니오 |
| 부트 스택에 쓸 수 있음 | 예 |
| 커널 text의 identity 매핑을 읽을 수 있음 | 예, 사용자 테이블이 대체하기 전까지 |

하나라도 어긋나면 검사의 이름과 함께 부팅이 멈춥니다. 이 검사는 테이블을 만든 코드가 아니라 하드웨어가 실제로 워크하는 테이블을 시험합니다.

## 테스트 방법

- `crates/k0-mm/src/paging/tests.rs`의 호스트 단위 테스트는 두 그래뉼의 인덱스 산술, 모든 커널 권한의 W^X 속성, 실패한 워크 이후의 롤백, 위조되었거나 블록인 엔트리의 거부를 확인합니다. AArch64 호스트에서 실행됩니다.
- `tools/qemu-boot-test.sh`는 `k0: w^x checks pass` 줄을 요구합니다.

## 알려진 공백

- 풀 크기는 32개 테이블로 고정입니다. retype이 충분히 많은 서로 다른 주소 범위에 흩어지면 풀이 바닥나고 `RETYPE`은 `KERNEL_RESOURCE`를 반환합니다. 누수는 없지만 풀은 회수되지 않습니다.
- 매핑은 제거되지 않습니다. `revoke`가 없으므로 retype된 오브젝트는 커널 별칭에 영원히 매핑된 채 남습니다.
- 주소 공간 식별자(ASID)는 사용하지 않습니다. 다른 사용자 주소 공간으로 전환할 때마다 TLB 전체를 무효화합니다.
