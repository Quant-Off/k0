# 케이퍼빌리티, untyped 메모리, retype

[English](capabilities.md)

이 문서는 버전 0.1.0 기준 K0의 케이퍼빌리티 모델을 설명합니다. 루트 CNode, 부팅 시 남은 메모리가 untyped 케이퍼빌리티가 되는 과정, 사용자 공간이 `RETYPE`으로 untyped 메모리를 커널 오브젝트로 바꾸는 방법을 다룹니다. 코드는 `crates/k0-cap/src/lib.rs`에 있고, 시스템 콜 계층은 `kernel/src/main.rs`에 있습니다.

격리를 목적으로 이 내용에 의존하기 전에 "알려진 공백" 절을 먼저 읽어주세요. 0.1.0에서는 모든 태스크가 같은 케이퍼빌리티를 공유합니다.

## K0에서 케이퍼빌리티란

케이퍼빌리티는 루트 CNode의 슬롯에 들어 있는 엔트리입니다. 사용자 공간은 슬롯 번호로 케이퍼빌리티를 지칭하고, 커널은 시스템 콜마다 그 번호를 CNode에서 해석합니다. 커널 자원을 지칭하는 다른 방법은 없습니다. 메모리나 다른 태스크를 바꾸는 시스템 콜은 항상 바꿀 오브젝트의 케이퍼빌리티를 받습니다. `YIELD`나 `EXIT`처럼 호출자 자신에 관한 호출만 케이퍼빌리티 없이 호출한 태스크에 작용합니다.

루트 CNode의 슬롯은 32개입니다. 슬롯 0에는 항상 null 케이퍼빌리티가 들어 있어서, 0으로 채운 인자는 아무것도 지칭하지 않습니다.

| 종류 | 생성 시점 | 부여하는 권한 |
| --- | --- | --- |
| `RootTcb` | 부팅 시 | 아직 없음. 실행 중인 루트 태스크를 표시하며 재설정할 수 없음 |
| `AddrSpace` | 부팅 시 | 루트 태스크의 주소 공간에 매핑하고 TCB를 그 주소 공간에 바인딩할 권한 |
| `Console` | 부팅 시 | 디버그 콘솔에 바이트를 쓸 권한 |
| `Untyped` | 부팅 시 | retype할 수 있는 물리 메모리 구간 |
| `Frame` | `RETYPE`으로 | 사용자 공간에 매핑할 수 있는 1 그래뉼의 메모리 |
| `PageTable` | `RETYPE`으로 | 주소 공간에 설치할 수 있는 페이지 테이블 하나 |
| `Tcb` | `RETYPE`으로 | 설정하고 재개할 수 있는 태스크 |
| `Endpoint` | `RETYPE`으로 | 동기 IPC의 랑데부 지점 |

케이퍼빌리티에는 권한 비트가 없습니다. 슬롯을 가진다는 것은 오브젝트의 권한 전체를 가진다는 뜻입니다.

## 부팅 시 루트 CNode 채우기

`bootstrap`은 정해진 순서로 CNode를 채웁니다. null 케이퍼빌리티, `RootTcb`, `AddrSpace`, `Console`, 그다음 untyped 케이퍼빌리티 순입니다.

untyped 케이퍼빌리티는 디바이스 트리가 보고한 RAM의 모든 바이트에서 모든 예약 구간을 뺀 범위를 덮습니다. 커널이 넘기는 예약 구간은 다음과 같습니다.

- 커널 이미지
- DTB
- 루트 태스크의 이미지, 스택, 페이지 테이블이 들어 있는 2 MiB 부트 프레임 윈도우
- DTB의 모든 펌웨어 예약 구간. memory reservation block과 `/reserved-memory`의 자식 노드 모두 해당

예약 구간은 서로 겹칠 수 있고 어떤 순서로 들어와도 됩니다. 각 메모리 리전마다 커서가 예약 구간을 주소 순서로 따라 앞으로 이동하면서 구간 사이의 틈을 내보내므로, 겹치는 예약은 자연스럽게 병합됩니다.

메모리 리전끼리는 겹쳐서는 안 됩니다. 두 리전이 겹치면 같은 물리 프레임이 두 untyped 케이퍼빌리티에 들어가 서로 다른 오브젝트 두 개로 retype될 수 있습니다. `bootstrap`은 이런 맵을 거부하고, 커널은 부팅을 중단합니다. 슬롯이 부족한 경우에도 부팅이 중단됩니다.

## bootinfo 페이지

이양 직전에 커널은 CNode에 대한 설명을 bootinfo 페이지에 씁니다. 이 페이지는 루트 태스크에 읽기 전용으로 매핑됩니다. 페이지에는 헤더(레이아웃 버전, 그래뉼 크기, 슬롯 수)와 슬롯마다 하나씩 종류를 담은 엔트리가 들어 있습니다. 물리 베이스와 크기는 untyped 엔트리만 공개합니다. 루트 태스크가 메모리를 계획하려면 이 값이 필요하기 때문입니다. 다른 모든 종류는 베이스와 크기가 0이므로 커널 오브젝트의 주소는 노출되지 않습니다.

이 페이지는 스냅샷입니다. 이후 `RETYPE`으로 만든 케이퍼빌리티는 여기에 나타나지 않습니다. 그 슬롯 번호는 `RETYPE`의 반환값으로 돌아옵니다.

## Retype

`RETYPE`은 untyped 슬롯과 오브젝트 타입을 받아 정확히 1 그래뉼 크기의 새 오브젝트 하나를 만듭니다.

각 untyped 케이퍼빌리티에는 워터마크가 있습니다. 베이스부터 세어 얼마나 사용했는지를 나타내는 값입니다. retype은 워터마크를 그래뉼 단위로 올림하고, 다음 그래뉼을 새 오브젝트로 가져가며, 워터마크를 그 뒤로 옮깁니다. 워터마크는 증가만 하므로 같은 untyped 케이퍼빌리티에서 떼어 낸 두 오브젝트는 겹치지 않고, 한 번 retype된 메모리는 다시 나눠 주지 않습니다.

검사 순서가 중요합니다.

1. 소스 슬롯이 존재하고 untyped 케이퍼빌리티를 담고 있어야 합니다.
2. CNode에 빈 슬롯이 있어야 합니다.
3. 올림한 워터마크에 1 그래뉼을 더한 값이 untyped 범위 안에 들어와야 하며, 모든 덧셈은 오버플로를 검사합니다.
4. 여기까지 통과한 뒤에야 커널이 메모리를 준비합니다. `sys_retype`의 콜백이 그래뉼을 커널 별칭에 매핑하고([memory_KR.md](memory_KR.md) 참고) 0으로 채웁니다.
5. 준비가 성공한 경우에만 워터마크를 옮기고 새 케이퍼빌리티를 다음 빈 슬롯에 넣습니다.

어느 단계든 실패하면 아무것도 바뀌지 않습니다. 워터마크, 슬롯 수, 커널 테이블 풀이 모두 이전 그대로이고, 호출자는 에러 코드를 받습니다.

0으로 채우는 것은 보안 단계이면서 동시에 설계상의 선택입니다. 메모리의 이전 내용이 새 오브젝트로 새어 나가는 것을 막습니다. 또한 0으로 채운 프레임이 그 자체로 유효한 초기 오브젝트가 됩니다. 0으로 채운 TCB는 `Inactive` 상태이고, 0으로 채운 엔드포인트는 큐가 비어 있습니다. 어떤 오브젝트도 추가 초기화가 필요하지 않습니다.

## 새 케이퍼빌리티 사용하기

| 시스템 콜 | 필요한 케이퍼빌리티 |
| --- | --- |
| `MAP` | `Frame` 또는 `PageTable`, 그리고 타겟을 지정하는 `AddrSpace` |
| `TCB_CONFIGURE` | `Inactive` 상태의 `Tcb`와 `AddrSpace` |
| `TCB_RESUME` | `Stopped` 상태의 `Tcb` |
| `SEND`, `RECV`, `CALL`, `REPLY_RECV` | `Endpoint` |
| `DEBUG_PUTC` | `Console` |

CNode에서 채워진 부분을 넘어선 슬롯 번호는 `BAD_SLOT`을 반환합니다. 종류가 맞지 않는 채워진 슬롯은 `BAD_CAP`을 반환하고, `RETYPE`에서는 `NOT_UNTYPED`를 반환합니다. null 슬롯 0은 종류가 맞지 않는 슬롯으로 취급됩니다.

## 테스트 방법

- `crates/k0-cap/src/tests.rs`의 호스트 단위 테스트는 수천 개의 무작위 레이아웃에서 bootstrap이 정확히 "메모리에서 예약 구간을 뺀 것"을 만드는지, 잘못되었거나 겹치는 리전이 거부되는지, 워터마크가 정렬되어 있고 단조 증가하는지, 준비 실패가 흔적을 남기지 않는지, 잘못된 소스가 준비 단계 전에 거부되는지, retype을 무작위로 이어 붙여도 겹치는 오브젝트가 생기지 않는지를 검사합니다.
- 루트 태스크 자가 테스트는 모든 오브젝트 타입을 retype하고, retype된 프레임이 0으로 읽히는지 확인하며, null 슬롯과 잘못된 오브젝트 타입에 대한 거부 경로를 확인합니다.

## 알려진 공백

K0 0.1.0이 태스크 간 격리를 제공하지 않는 이유는 다음과 같습니다.

- **모두가 하나의 CNode를 씁니다.** 모든 태스크가 같은 루트 CNode에서 슬롯 번호를 해석하므로 모든 태스크가 모든 케이퍼빌리티를 가집니다. 이것이 [SECURITY_KR.md](../SECURITY_KR.md)의 어드바이저리 GHSA-vmpv-qc49-3p6r입니다.
- **파생이 없습니다.** 케이퍼빌리티 파생 트리가 없고, 권한을 줄이거나 배지를 붙인 사본을 만드는 `MINT`도 없으며, `revoke`도 없습니다.
- **전송이 없습니다.** IPC로 케이퍼빌리티를 보낼 수 없습니다.
- **재사용이 없습니다.** retype된 메모리는 untyped 케이퍼빌리티로 돌아가지 않습니다.

README에 기록된 방향은 태스크별 CSpace와 `AddrSpace` retype을 먼저 구현하고, 그다음 `MINT`와 `revoke`를 갖춘 파생 트리, 그다음 IPC를 통한 케이퍼빌리티 전송입니다.
