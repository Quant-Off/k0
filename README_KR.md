# K0 Microkernel

<div align="center">

[English](README.md) | 한국어

</div>

K0는 64비트 ARM(AArch64) 컴퓨터용 작은 운영체제 커널이며 Rust로 작성했습니다. 마이크로커널이라서 커널은 커널 안에서만 할 수 있는 일, 그중에서도 프로그램끼리 떼어 놓는 일만 하고, 나머지는 그 위에서 일반 프로그램으로 돌리도록 설계했습니다. 프로그램은 열쇠를 가진 자원만 쓸 수 있습니다. 이 열쇠를 케이퍼빌리티(capability)라고 부르며 설계는 seL4 커널을 따릅니다.

> [!IMPORTANT]
> K0는 QEMU의 가상 ARM 컴퓨터에서 동작합니다. Apple Silicon용 빌드는 컴파일까지만 되고 아직 부팅해 보지 않았습니다. 지금의 K0는 고보안 시스템의 격리 코어를 연구하는 플랫폼입니다. 부팅해서 자신의 보안 성질을 스스로 확인하지만, 아직 그 자체로 쓸모 있는 일을 하지는 않습니다.

## 보안 상태

- `v0.1.0` 태그로 공개된 버전에는 **프로그램 사이의 격리가 없습니다**. 게시된 보안 어드바이저리(알려진 결함에 대한 공개 공지)가 그대로 적용됩니다.
- 현재 `main` 브랜치(릴리즈되지 않음)는 메모리와 쓸 수 있는 열쇠를 기준으로 프로그램을 서로 떼어 놓습니다. 하지만 **가용성**은 지키지 못합니다. **프로그램 하나가 여전히 시스템 전체를 멈출 수 있습니다.**
- 서비스가 멈추면 곤란한 곳에서는 믿을 수 없는 코드를 K0 위에서 실행하지 마세요.

격리 모델, 알려진 어드바이저리(advisory), 취약점 신고 방법은 [SECURITY_KR.md](SECURITY_KR.md)에 있습니다.

## 주요 특징

- **커널 heap 없음**: 커널에는 자기만의 메모리 할당기(heap)가 없습니다. 작은 고정 저장소 말고는 프로그램이 넘겨준 메모리만 사용합니다.
- **신뢰 대신 열쇠**: 모든 자원은 열쇠로만 쓸 수 있습니다. 열쇠의 복사본은 원본보다 권한이 많을 수 없고, 열쇠를 회수하면 거기서 만든 복사본이 전부 사라집니다.
- **프로그램 분리**: 프로그램마다 자기 열쇠고리와 메모리 지도를 줄 수 있고, 그러면 서로의 메모리와 열쇠에 닿지 못합니다. 프로그램이 죽으면 그 프로그램만 멈춥니다.
- **재사용 전 소거**: 메모리를 다시 내줄 때마다 0으로 채웁니다.
- **쓰기와 실행은 동시에 불가**: 어떤 메모리도 쓰기와 실행이 동시에 되지 않습니다. 그 대가로 부팅 뒤에는 새 코드를 실행 가능하게 만들 수 없어서, 프로그램이 새 코드를 불러올 수 없습니다.
- **부팅 입력 불신**: 부팅 때 넘겨받는 하드웨어 설명은 공격자가 작성한 것처럼 검사합니다.

첫 프로그램이 부팅할 때마다 자가 테스트로 위 성질들을 확인합니다.

## 빠른 시작

```sh
# 저장소 클론 후 이동
$ git clone https://github.com/Quant-Off/k0.git
$ cd k0

# K0를 빌드 후 QEMU에서 부팅 (종료는 Ctrl-A 후 X)
$ cargo virt
```

필요한 도구, 출력 읽는 법, 자동 테스트 실행 방법은 [USAGE_KR.md](USAGE_KR.md)에 있습니다.
